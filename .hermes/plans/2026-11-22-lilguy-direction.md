# Decision before the next training run

Goal: choose the next investment by usefulness on ordinary, explicitly requested shell work, not by the last failed benchmark case. Keep MiniCPM r8/interface v3 frozen, keep Qwen as a size reference, and leave held-out untouched. No launch or interface change is part of this plan.

1. Ask Ivy for three frequent jobs in her own words, the expected output, and which mistakes would make each unusable. Use synthetic fixtures, not private workspace content. For each, compare using lilguy with the simplest realistic alternative (one shell command, a fixed helper, or doing it manually). Record human choices and corrections alongside exact effects, original preservation, handoff and latency.
2. Map the 80-task roster onto those workflows: covered, absent, repeatedly passing, unstable or repeatedly failing across r8 seeds. Do not count two seeds or paraphrases as independent tasks. Rank opportunities by frequency, consequence, number of distinct useful tasks affected, and cost to test. Permission translation has unusually clean diagnostic evidence, not yet evidence it deserves a dedicated UI.
3. Choose one frequent failure family and one known-good neighboring family. Write at least three fresh development fixtures with different paths, layouts and phrasings, exact expected effects, and negative controls. Freeze success criteria before inference. Score normal input first, then change only one suspected burden on a fresh fixture (target supplied, or literal bytes supplied, or mode supplied). Preserve guards and cost the extra human work. Repeat on both existing r8 seeds. Record the first consequential mistake and the complete final outcome, including honest stops.
4. Route by evidence. If a low-friction hint or deterministic operation rescues several distinct fixtures across seeds without harming controls, propose a numbered v4; if a deterministic helper does the entire job, prefer the helper. If a feasible next decision is absent or mislabeled in training, propose a targeted r10 test with a matched control. If neither rescue works, distinguish faulty grading from a harder capability limit using a competent reference before increasing model size or narrowing scope. Stop if no proposal materially improves a workflow Ivy values. Report wins, losses, review burden and misses; keep the 18-case safety gate separate and mandatory for release.
